# LexRadar: запуск через Яндекс SMTP

Код подготовлен от main v1.3.0 в PR №4. Production-сервер не изменён. Реальные авторизация и доставка из рабочей среды Codex не проверены: доступа к серверу, паролю приложения и ящику нет. Ни тесты, ни наличие переменных не подтверждают доставку.

## Настройки

После одобренного развёртывания кода PR оставить форму выключенной. В /var/www/golwebstudio/.env.local (или секретном окружении службы) должны быть:

~~~dotenv
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=golkonst@yandex.ru
SMTP_PASS=
SMTP_FROM=golkonst@yandex.ru
MAIL_TO=golwebstudio@mail.ru
LEXRADAR_FORM_ENABLED=false
LEXRADAR_SITE_ORIGIN=https://www.golwebstudio.ru
~~~

SMTP_PASS заполнить через редактор правильным паролем приложения Яндекса для почты. Не использовать основной пароль аккаунта, историю команд или логи. Пароль не передавать аргументом команды, не вставлять в GitHub/чат. Файл должен читаться пользователем службы, с правами 600. Инфраструктуру и рабочую службу в рамках этого PR никто не меняет.

SMTP_PASSWORD поддерживается как прежнее имя SMTP_PASS; LEAD_TO_EMAIL — как прежнее имя MAIL_TO. Лучше оставить по одному имени из пары. Если оба заданы с разными значениями, включая пустое, отправка и готовность формы блокируются. Одинаковые значения совместимы. Пустой заданный получатель также считается ошибкой, а не заменяется незаметно значением по умолчанию.

Прежний режим YANDEX_EMAIL / YANDEX_PASSWORD с IPv6:587 сохранён только для совместимости при отсутствии всех SMTP_*. Для этого запуска использовать именно настройки выше. Новых зависимостей и отдельного почтового сервиса не добавлено.

## Одна команда диагностики на сервере

После одобренного развёртывания кода PR и установки его зависимостей:

~~~sh
cd /var/www/golwebstudio && npm run smtp:diagnose -- --production-test
~~~

Запускать под пользователем сайта, из каталога сайта. Скрипт:

1. Читает только файлы окружения Next.js production: .env.production.local, .env.local, .env.production, .env. Применяет штатный @next/env, не выполняет файл как shell-скрипт.
2. Выводит для известных имён MISSING / EMPTY / SET, имя источника, пустые определения, дубликаты, перекрытые ключи, конфликты алиасов и предупреждения о формате. Значения, длины, хеши паролей и ответы SMTP не выводятся. Повтор одного ключа в одном файле блокирует сетевую проверку.
3. Использует приоритет Next: окружение запущенной команды, затем указанные файлы по порядку. shadowedKeys показывает перекрытия между источниками; source — источник эффективного значения. Перекрытия сами по себе допустимы, но могут объяснять использование старого пароля. Скрипт не извлекает окружение существующего PM2-процесса; если оно отличается от shell, результат относится к среде этой команды. Согласовать источник конфигурации перед последующим штатным перезапуском, не публикуя pm2 env/dump.
4. Проверяет соответствие цели: smtp.yandex.ru:465, TLS, golkonst@yandex.ru как пользователь и отправитель, golwebstudio@mail.ru как получатель. При несовпадении — YANDEX_TARGET_MISMATCH, без соединения и отправки.
5. Проверяет соединение TLS с сертификатом, затем SMTP-авторизацию через Nodemailer verify. После успешной авторизации вызывает существующий email-service ровно один раз для синтетического письма. Автоповторов нет.
6. Печатает этапы CONNECTION_OK, SMTP_AUTH_OK, SMTP_ACCEPTED либо безопасный код ошибки и числовой ответ SMTP, если доступен. TEST_REFERENCE содержит UUID для поиска письма. SMTP_ACCEPTED выдаётся только после принятия нужного получателя без отказов.

Код завершения 0 означает прохождение запрошенных проверок, 1 — ошибку. SMTP_ACCEPTED и DIAGNOSTIC_OK не доказывают появления письма во входящих: найти письмо с Test ID в golwebstudio@mail.ru, включая спам. При DELIVERY_UNCONFIRMED сначала проверить ящик, не повторять вслепую.

Без флагов npm run smtp:diagnose только проверяет конфигурацию, без сети. --verify проверяет соединение и авторизацию без письма. Прежний --send-test теперь равнозначен --production-test: сначала авторизация, затем одна отправка на строго заданную цель. Скрипт никогда не редактирует .env, PM2, Nginx или флаг формы.

## Если EAUTH

EAUTH, обычно вместе с 535, означает отказ на этапе авторизации; этот код сам по себе не различает неверный пароль и ограничения аккаунта. Проверить:

- SMTP_PASS / SMTP_PASSWORD: EMPTY, дубликаты, конфликты, source и shadowedKeys. Переменная shell/PM2 имеет приоритет над файлом. Скрипт не выбирает другой пароль и не перебирает варианты.
- Полный логин golkonst@yandex.ru и пароль приложения именно этого аккаунта. При необходимости владелец выпускает новый пароль приложения для почты в интерфейсе Яндекса и заменяет только конфигурацию сервера.
- Разрешение доступа почтовых клиентов по SMTP/IMAP и ограничения безопасности аккаунта в настройках Яндекса. Не отключать TLS и проверку сертификата.
- CHECK_DOTENV_EXPANSION: знак $ обрабатывается загрузчиком Next. Проверить экранирование по правилам .env; кавычки сами по себе не гарантируют отсутствия подстановки. CHECK_UNQUOTED_COMMENT: # без кавычек начинает комментарий. CHECK_PASSWORD_WHITESPACE: проверить пробелы при копировании. Скрипт не исправляет и не обрезает пароль.

ENOTFOUND / EDNS / EAI_AGAIN указывают на DNS; ECONNREFUSED / ETIMEDOUT — соединение/таймаут; ETLS / ошибки сертификата — TLS. Ошибка доставки после SMTP_AUTH_OK может относиться к отправителю, получателю, ограничениям или сетевому сбою; это не успех заявки.

## Включение формы после успешного теста

1. Получить SMTP_AUTH_OK и SMTP_ACCEPTED на целевом сервере и подтвердить контрольное письмо в ящике. Пока это не выполнено, LEXRADAR_FORM_ENABLED=false.
2. Проверить существующий Nginx/proxy: Node-порт закрыт извне, доверенный IP-заголовок перезаписывается, размер тела и массовые запросы ограничены. Не менять инфраструктуру без отдельного разрешения.
3. Указать LEXRADAR_ABUSE_MODE=single-process только при одном Node/PM2-процессе. Без доверенного IP применяется общий лимит 5 попыток / 10 минут на процесс. Если текущий Nginx надёжно перезаписывает X-Real-IP, можно указать LEXRADAR_TRUST_PROXY=true и LEXRADAR_CLIENT_IP_HEADER=x-real-ip после проверки этой границы. Для нескольких workers/реплик нужен режим edge и подтверждённый общий ingress-limit; флаг LEXRADAR_EDGE_RATE_LIMIT_CONFIRMED=true сам лимит не создаёт.
4. На отдельном стенде проверить форму, юридические ссылки, негативные ответы, origin и лимиты по [полному чек-листу](./lexradar-smtp-launch-checklist.md). На production оставить false до успешных проверок.
5. Только после разрешения владельца на изменение production установить LEXRADAR_FORM_ENABLED=true в согласованном источнике и штатно перезапустить службу, например pm2 restart golwebstudio --update-env. Не запускать эту команду в рамках подготовки PR.
6. Отправить одну помеченную TEST заявку через реальную страницу /lexradar и подтвердить её получение в ящике. UI сообщает успех только после ответа SMTP. Если что-то не работает, вернуть флаг false и штатно перезапустить службу; на странице остаётся альтернативный email.

URL, имя, email и отдельное согласие обязательны; телефон и комментарий необязательны. Заявки рассматриваются вручную, автоматический аудит не вызывается. После сетевого таймаута UI не сообщает успех и блокирует повтор до уточнения статуса по email.
