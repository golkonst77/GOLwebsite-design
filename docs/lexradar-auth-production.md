# Яндекс AUTH: один диагностический запуск

Production и пароль не менялись. Цель: SMTP_AUTH_OK, SMTP_ACCEPTED и ручное подтверждение письма в golwebstudio@mail.ru. Локальные тестовые SMTP-серверы не подтверждают доставку Яндекса.

## Изменения

- Для smtp.yandex.ru (и сохранённого старого Yandex-транспорта) механизм AUTH теперь явно LOGIN. Раньше Nodemailer выбирал первый механизм из EHLO; наличие type=LOGIN в его внутреннем объекте не фиксировало механизм SASL. Само по себе это не доказывает причину production 535.
- SMTP_AUTH_METHOD=PLAIN позволяет явно выбрать второй стандартный механизм. Другие значения отклоняются. Пароль не меняется, не обрезается и не нормализуется.
- TLS 465 остаётся implicit TLS, минимальная версия 1.2, проверка сертификата обязательна. Для старого порта 587 по-прежнему обязателен STARTTLS. У Яндекса задан стабильный EHLO www.golwebstudio.ru.

## Запуск

После одобренного развёртывания этого PR:

~~~sh
cd /var/www/golwebstudio && npm run smtp:auth
~~~

Без развёртывания можно выполнить тот же публичный scripts/diagnose-yandex-auth.cjs из фиксированного commit SHA через stdin Node. Готовая команда приведена в PR/ответе. HTTP-запрос получает только код с GitHub, пароль и результаты в него не включаются.

Скрипт использует установленный Nodemailer, существующие getSmtpConfig / createEmailSender и штатный Next production env loader. Нужен уже используемый проектом tsx; новые зависимости не требуются. Запускать под пользователем сайта из каталога сайта. Окружение команды может отличаться от уже работающего PM2: скрипт не извлекает его память, историю или логи.

Скрипт проверяет точную цель smtp.yandex.ru:465, пользователя/отправителя golkonst@yandex.ru, получателя golwebstudio@mail.ru, отсутствие дубликатов. Он не редактирует файлы, PM2/Nginx и флаг формы.

## Что будет видно

- TLS_OK: фактически согласованный TLSv1.2/1.3 и успешная проверка сертификата.
- SMTP_CAPABILITIES: известные механизмы AUTH из EHLO.
- AUTH_ATTEMPT: явно выбранный LOGIN или PLAIN.
- CREDENTIAL_FORWARDING_OK: пароль в объекте фактической SMTPConnection точно совпадает со строкой, переданной из существующей конфигурации. Само значение и его производные не выводятся.
- SMTP_SERVER_REPLY: все строки серверного ответа с кодами и разделителями, после консервативного удаления чувствительного текста. Сохраняются только стандартные причины из фиксированного словаря; неизвестный текст, адреса, hostname/IP, URL, session/message ID и токены заменяются [REDACTED]. SASL-challenge скрывается целиком, base64 не печатается и не декодируется для вывода.
- SMTP_FAILED: этап, выбранный механизм, безопасный код Nodemailer, SMTP-код и очищенный ответ. Сырые Error.message/stack, client-команды и AUTH-payload не выводятся. Обычный debug/logger Nodemailer в production не включается: изолированный диагностический logger отбрасывает все client-записи и пропускает только очищенные server replies.

Сначала используется SMTP_AUTH_METHOD, если задан, иначе LOGIN. Если механизм не объявлен сервером, реквизиты ему не передаются. После EAUTH именно с ответом 535 допустима одна проверка второго объявленного механизма с тем же неизменным паролем, в новом TLS-соединении. Максимум две попытки авторизации; без циклов и перебора паролей. На TLS/сетевой ошибке, ограничении аккаунта, rate limit или требовании web-login повторов нет.

После успешного AUTH отправляется ровно одно синтетическое письмо через тот же авторизованный SMTPConnection и существующий email-service. Повторной авторизации для отправки нет. После любого результата доставки fallback запрещён, чтобы не создать дубликат при неопределённом результате.

## Результат и включение

Если получены SMTP_AUTH_OK и SMTP_ACCEPTED, найти письмо по testId в golwebstudio@mail.ru, включая спам. Скрипт намеренно оставляет inboxReceiptConfirmed=false: проверить ящик должен владелец. AUTH_METHOD_FOR_PRODUCTION сообщает проверенный механизм. Если сработал только PLAIN, после разрешения на production указать SMTP_AUTH_METHOD=PLAIN; если LOGIN — оставить LOGIN.

После подтверждённого письма выполнить сквозной тест формы/защиты по [инструкции запуска](./lexradar-yandex-production.md). Только с отдельным разрешением владельца применить код/окружение, перезапустить службу и включить форму. Скрипт сам её не включает.

Если оба механизма дают 535, нужны только безопасные JSON-статусы этого запуска. Пароль не запрашивать, не менять и не публиковать. Ответ покажет, относится ли отказ к разрешению AUTH/ограничению аккаунта/требованию web-login либо сервер сообщает только общий отказ; общий 535 не позволяет достоверно выбрать одну причину.
