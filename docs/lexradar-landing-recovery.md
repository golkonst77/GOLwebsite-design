## Просмотр

Сначала сохранить свои незакоммиченные изменения отдельно. Для чтения истории:

```sh
git fetch origin
git log --oneline --decorate origin/feat/lexradar-landing-2026-10-17
git diff --stat a976ef766895e40c86005804eec6244121e71bca origin/feat/lexradar-landing-2026-10-17
git show cf447d44f790de5eddba2d4e99de6c19616403e0
```

Проверить точку: `git rev-parse origin/checkpoint/gol-before-lexradar-2026-10-17` должен дать исходный SHA.

## Безопасно открыть исходную версию

Создать отдельный каталог вне активного checkout, не менять main и не терять текущие изменения:

```sh
git worktree add --detach ../gol-before-lexradar a976ef766895e40c86005804eec6244121e71bca
```

Установить зависимости и запускать проверки в этом каталоге отдельно. Потребуются собственные локальные настройки окружения; секреты не входят в Git и не восстанавливаются этим действием.

## Промежуточная версия

Для любого SHA таблицы использовать отдельный каталог, например:

```sh
git worktree add --detach ../gol-lexradar-cp3 53c9904f0c4811efc073bc62b4317d3270440ccc
```

Для продолжения разработки создать новую ветку от выбранного SHA (`git switch -c recovery/lexradar-cp3` внутри этого worktree), не передвигать старые опубликованные ссылки. У CP2/CP3 ещё нет онлайн-формы; это ожидаемое состояние, а не повреждение.

## После возможного будущего merge

1. Узнать реальный способ слияния и SHA через GitHub PR. Не подставлять нынешний SHA ветки вместо merge/squash SHA.
2. От актуального `origin/main` создать отдельную rollback-ветку.
3. При merge-коммите с двумя родителями проверить порядок родителей и использовать `git revert -m 1 <реальный_merge_SHA>` только если первым родителем является main. Для squash — `git revert <реальный_squash_SHA>`. При rebase отменять только относящиеся к задаче коммиты в обратном порядке, учитывая последующие зависимости.
4. Разобрать конфликты вручную, проверить diff, типы, тесты и build. Создать отдельный PR отката. Не переписывать main и не выполнять force push.
5. Слияние rollback PR и публикация — только отдельными разрешёнными действиями владельца. Откат Git сам по себе не восстанавливает production.

## Работающий сайт

В этом задании production не развёртывался, Vercel/серверная конфигурация не менялись. Если после будущей публикации нужен возврат production, владелец должен отдельно выбрать прежний проверенный deployment либо собрать нужный Git SHA штатным способом. Учитываются окружение, секреты, DNS, runtime-флаг формы и совместимость инфраструктуры. Не включать форму только потому, что восстановлен код: реальная доставка должна быть отдельно проверена.
