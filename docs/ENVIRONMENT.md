# Переменные окружения

Имена и требования описаны ниже; реальные значения production и секреты не копировать в GitHub. `.env.example` — шаблон, а не резервная копия сервера. Не использовать `NEXT_PUBLIC_*` для SMTP.

## Загрузка

Для production Next.js приоритет: уже заданное окружение процесса → `.env.production.local` → `.env.local` → `.env.production` → `.env`. В тестовом режиме правила отличаются; диагностика production должна запускаться без NODE_ENV=test. Более приоритетный источник может перекрыть исправленный файл.

Пароль может содержать специальные символы; не менять его пробелы/кавычки наугад. Интерактивный установщик проверяет сохранение значения через установленный загрузчик Next.js, не выводя значение, длину, хеш или фрагменты.

## SMTP

| Имя | Назначение |
|---|---|
| SMTP_HOST | Сервер Mail.ru; другой провайдер отклоняется текущим кодом |
| SMTP_PORT | Порт подключения, согласованный с TLS |
| SMTP_SECURE | Строковое true для TLS с начала соединения; проверка сертификата обязательна |
| SMTP_AUTH_METHOD | Поддерживаются LOGIN и PLAIN; используется установленный режим |
| SMTP_USER | Почтовая учётная запись |
| SMTP_PASS | Пароль приложения: только секретное окружение или закрытый env-файл |
| SMTP_FROM | Адрес отправителя |
| MAIL_TO | Единственный получатель, проверяемый кодом |

SMTP_PASSWORD и LEAD_TO_EMAIL — совместимые имена SMTP_PASS и MAIL_TO; разные значения в одной паре блокируют отправку. Старые YANDEX_EMAIL/YANDEX_PASSWORD больше не используются. Установщик устраняет определения старых SMTP/Yandex/recipient aliases, не удаляя остальные настройки.

## Допуск формы LexRadar

| Имя | Требование |
|---|---|
| LEXRADAR_SITE_ORIGIN | Канонический origin сайта: схема и домен, без /lexradar, query/hash и userinfo; должен совпадать с Origin браузера. HTTPS; HTTP только для loopback-разработки |
| LEXRADAR_ABUSE_MODE | Явно single-process либо edge |
| LEXRADAR_TRUST_PROXY | Ровно true только при проверенном доверенном proxy; прямой порт Node закрыт извне |
| LEXRADAR_CLIENT_IP_HEADER | При доверии proxy: x-real-ip либо x-vercel-forwarded-for; proxy обязан перезаписывать заголовок |
| LEXRADAR_EDGE_RATE_LIMIT_CONFIRMED | Ровно true в режиме edge только после проверки реального общего ingress-limit |
| LEXRADAR_FORM_ENABLED | Ровно строчное true после проверки доставки и готовности; TRUE не включает форму |

`getLexradarConfig().ready` требует валидный origin, конфигурацию SMTP/получателя и выбранный abuse mode. В edge дополнительно обязательны доверенный IP-заголовок и подтверждение общего лимита. `enabled` проверяется отдельно: форма доступна только при `enabled && ready`.

`single-process` допустим только при одном процессе приложения. Встроенный limiter — 5 попыток за 10 минут. Без доверенного IP-заголовка все посетители делят общий bucket; это консервативное ограничение, а не индивидуальный лимит. Для нескольких workers нужен общий limiter; выставление флага подтверждения само по себе его не создаёт.

На новых установках форма выключена. Отсутствие настроек нельзя обходить удалением серверных проверок.

## Необязательные Telegram-уведомления

Только сервер: `TELEGRAM_NOTIFICATIONS_ENABLED` (ровно true, default false), `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (default пустые). Не использовать NEXT_PUBLIC_, не передавать из заявки и не хранить реальные значения в Git. Отсутствие этих настроек не влияет на ready/enabled формы и SMTP. [Настройка, контрольное сообщение и ограничения](TELEGRAM_NOTIFICATIONS.md).
