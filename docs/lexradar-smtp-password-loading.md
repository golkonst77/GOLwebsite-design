# SMTP 535: проверка обработки SMTP_PASS без замены пароля

CONFIG_OK / CONNECTION_OK / EAUTH 535 подтверждают достижимость сервера и отказ авторизации, но не определяют причину отказа. Непустое значение и отсутствие дубликатов не доказывают, что SMTP получает исходный пароль.

В main после PR №4:

- scripts/diagnose-smtp.ts использует loadEnvConfig(cwd, false) из @next/env.
- Приоритет: окружение команды, .env.production.local, .env.local, .env.production, .env.
- Next 16.4.2 сначала применяет dotenv-разбор (кавычки, комментарии, пробелы и escape-последовательности), затем dotenv-expand (подстановка $VARIABLE). Одинарные кавычки не отключают второй этап.
- lib/smtp-config.ts передаёт SMTP_PASS в auth.pass без trim; проверка trim используется только для обнаружения пустого значения. В email-service пароль дополнительно не преобразуется.

## Проверка

Отдельный scripts/check-smtp-env.cjs не вызывает SMTP и не импортирует Nodemailer. Он не редактирует файлы, настройки или флаг формы. Вся проверка выполняется в памяти отдельного процесса. Вывод содержит только фиксированные статусы сравнения и фиксированное имя источника: нет пароля, длины, хеша, фрагментов или закодированных представлений.

Скрипт использует установленный на сервере @next/env, а не другую версию загрузчика. Копия лексических правил dotenv ограничена точной версией 16.4.2; при несовпадении версии, дубликатах SMTP_PASS, смене файлов во время чтения или ошибке чтения выдаётся безопасный отказ без выводов о пароле. Ошибки самого загрузчика не печатаются.

Из корня уже развёрнутого сайта можно запустить скрипт напрямую, без развёртывания/слияния PR:

~~~sh
cd /var/www/golwebstudio && node /путь/к/check-smtp-env.cjs
~~~

Также можно получить этот публичный скрипт по URL фиксированного commit SHA и передать его node через stdin. HTTP-запрос получает только код с GitHub; пароль, env и результаты сравнения в запрос не включаются. Сам Node-процесс работает без сети. Готовая команда с зафиксированным SHA приведена в отчёте.

## Интерпретация

| Статус | Значение |
|---|---|
| LOCAL_DOTENV_SYNTAX_TRANSFORMED | Разбор файла применил значимые правила синтаксиса к записи: например комментарий без кавычек, обрезание незащищённых пробелов или escape-последовательности двойных кавычек |
| LOCAL_DOTENV_SYNTAX_PRESERVED | Между буквальным содержимым записи (без синтаксических кавычек) и dotenv-разбором различий нет |
| LOCAL_FILE_SELECTED | Эффективный источник SMTP_PASS — .env.local |
| LOCAL_FILE_OVERRIDDEN | Источник другой: окружение команды или файл выше по приоритету |
| SELECTED_VALUE_NEXT_CHANGED | Выбранное исходное значение после dotenv-разбора (либо inherited env) отличается от фактического значения после Next |
| NEXT_CHANGE_EXPECTED_DOLLAR_ESCAPE_REMOVAL | Различие полностью объясняется штатным удалением escape перед знаком доллара; само по себе это не повреждение пароля |
| NEXT_CHANGE_BEYOND_DOLLAR_ESCAPES | Есть изменение сверх снятия escape; при выбранном .env.local это подтверждает преобразование на этапе Next, например подстановку переменной |
| SELECTED_VALUE_NEXT_UNCHANGED | На этапе Next выбранное значение сохранилось |
| LOCAL_PARSED_DIFFERS_FROM_EFFECTIVE | Результат dotenv-разбора локального файла отличается от фактически используемого значения; причину уточняют статусы источника и этапа Next |
| PASSWORD_ALIAS_CONFLICT | SMTP_PASSWORD тоже задан, но отличается от SMTP_PASS; конфигурация SMTP будет отклонена |

Скрипт не знает исходный пароль в интерфейсе Яндекса. Поэтому применение правил .env — установленный факт обработки, но не автоматическое доказательство порчи: комментарий, пробелы или escape могли быть записаны намеренно. Если выбран .env.local, синтаксис сохранён и Next ничего не изменил, гипотеза о таком преобразовании этой записи не подтверждается.

Проверяется окружение диагностической команды, а не память уже работающего PM2. Скрипт не извлекает пароль из PM2, истории команд, логов или иных источников. Если PM2 использует другое окружение, результаты команды не доказывают равенство значений в нём.

## Точечное исправление, только после результата и разрешения

Сам пароль приложения менять не нужно. Исправляется только представление того же значения в .env:

- Для буквального $ поставить escape перед долларом по правилам Next. Одних одинарных/двойных кавычек недостаточно. После исправления ожидаемое снятие escape будет отмечено отдельно и не считается новым искажением.
- Если # ошибочно стал комментарием или должны сохраниться краевые пробелы, заключить полное значение в подходящие синтаксические кавычки. Пробелы, являющиеся частью исходного пароля, не удалять.
- Если двойные кавычки превращают буквальные последовательности обратного слеша с n/r в управляющие символы, использовать подходящее представление без такого преобразования. Не проводить массовую замену символов наугад.
- Если файл перекрыт процессом/другим файлом, исправлять выбранный источник конфигурации, а не файл, который не используется.

Не публиковать строку с паролем, не передавать её аргументом команды, не выводить её для сверки. Проверку после одобренной правки выполнить повторно. Затем можно использовать штатную SMTP-авторизацию Яндекса; это отдельная проверка. Этот инструмент не изменяет production и не включает форму.
