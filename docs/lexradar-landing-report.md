## Реализовано

- `/lexradar`: первый экран, пять карточек юридических рисков, направления проверки, результат бесплатной диагностики, платные документы и инструкции вебмастеру, партнёрский блок, форма.
- Премиальная тёмная гамма GØL, золотые CTA, оранжевые предупреждения, адаптивные сетки и типографика, доступные focus/labels/состояния формы. Без фиктивных отзывов, метрик и государственной символики.
- Главная: отдельный промоблок перед FinalCTA; desktop/mobile ссылка LexRadar.
- SEO: уникальные title/description, canonical, один H1, H2/H3, Open Graph с собственной SVG-картинкой. SVG поддерживается не всеми социальными платформами; для рекламного запуска желательно подготовить PNG-превью.
- Пять стандартных UTM-меток переносятся с главной и передаются с заявкой. Внутренние якоря не сбрасывают query string. В UTM нельзя помещать персональные данные.
- Отдельный API использует текущий `sendEmail`, не меняя прежнюю форму. Обязательные имя/email/URL/согласие, необязательные телефон/комментарий. URL не сканируется сервером.
- Отдельный текст согласия, обновлена политика по собираемым полям и цели LexRadar.

## Юридические ограничения

Текущую редакцию КоАП на 17.10.2026 подтвердить не удалось: правовая база Consultant.ru заблокирована сетевой политикой (CONNECT 403). Поэтому суммы 300 000 / 700 000 / 60 000 / 3 000 000 ₽ не опубликованы как действующие. Финансовый акцент «до 700 000 ₽» и числовой подзаголовок заменены безопасной формулировкой. Номера частей ст. 13.11 взяты из задания и требуют актуальной правовой проверки вместе с применимостью составов. Для письменного согласия указано условие обязательности по закону. Инциденты — общее предупреждение, не результат внешнего аудита.

Перед публикацией требуется актуальная правовая сверка норм и согласования данных/условий услуги. Исполнитель — ИП Голубев, сведения об операторе взяты из существующей политики. Новые реквизиты не выдумывались. Сроки и цена платной услуги индивидуальные.

## Конфигурация и включение формы

Секреты задаются только в окружении сервера, не в Git:

- `YANDEX_EMAIL`, `YANDEX_PASSWORD`: существующие учётные данные SMTP.
- `LEAD_TO_EMAIL`: адрес получателя (по умолчанию существующий golwebstudio@mail.ru).
- `LEXRADAR_FORM_ENABLED=true`: включать лишь после контролируемого сквозного теста на непроизводственном стенде; до этого оставить отсутствующим/false.

SMTP-сервис сохранён: IPv6 Yandex, порт 587, STARTTLS, проверка сертификата. На стенде/сервере нужен доступ к этому адресу и протоколу. Никакая новая инфраструктура не добавлялась.

Reverse proxy должен передавать корректные публичные host/protocol, перезаписывать `X-Forwarded-For` доверенным адресом, ограничивать размер/время запроса. Иначе Origin-check может отклонять реальные запросы, а IP-limit — объединять пользователей или допускать подмену IP. Rate limit хранится в памяти процесса, сбрасывается после перезапуска и не синхронизирован между экземплярами. Для масштабирования потребуется уже существующий общий лимитер на уровне proxy; новый сервис в рамках задачи не создаётся.

API отвечает 200 только после положительного SMTP-ответа. Это подтверждает приём почтовым сервером, а не попадание в конечный ящик. При timeout пользователь предупреждён, что статус не подтверждён. При отсутствии конфигурации — 503, ошибка SMTP — 502, rate limit — 429, ошибки данных — 400; нет имитации успеха.

## Ручная приёмка до публикации

1. На отдельном стенде установить зависимости, `npm run build`, `npm start`. Production deploy этой задачей не выполнялся.
2. Открыть `/lexradar` на ширинах 360, 390, 768, 1440 px. Проверить переносы, отсутствие горизонтального скролла, cookie banner, фокус с клавиатуры и масштаб 200%.
3. С главной `/?utm_source=partner&utm_campaign=lexradar` перейти через промоблок и мобильное меню: параметры должны остаться. Кнопки первого экрана ведут к форме и рискам.
4. При выключенном флаге: видны уведомление и email, отправка недоступна. Проверить отдельные страницы согласия и политики.
5. На тестовом стенде настроить SMTP и временно включить флаг. Проверить required/email/URL, неверный телефон, отказ сервера, 429, повторную отправку. Незаполненный телефон должен приниматься.
6. Отправить одну помеченную тестовую заявку с разрешёнными тестовыми контактами, проверить получение письма, URL, UTM, reply-to, отметку согласия и время. Проверить отсутствие ложного успеха при отказе SMTP. Unit-тест не заменяет этот шаг.
7. Только после успешного сквозного теста и правовой/визуальной проверки решить о включении формы на production. Публикация и merge требуют отдельного разрешения владельца.
