# Зашифрованная копия конфигурации сайта

Инструмент не содержит адреса production, SSH-пользователя, доменов, имени PM2-приложения или его путей. Эти сведения читаются из **локального `backup.local.json`**, который нельзя публиковать. Пароли, токены и содержимое env в этот JSON не помещаются. Файл `backup.example.json` содержит только обозначения полей.

## На Windows: один раз

1. Скачать **SiteConfig-Backup.ps1** из этой папки. Это standalone-файл: Python-помощник встроен, скачивать весь репозиторий и развёртывать сайт не требуется.
2. Рядом создать `backup.local.json`, заполненный своими параметрами по `backup.example.json`. Локальные пути могут использовать `%USERPROFILE%`. В SSH-адресе указать пользователя и сервер; удалённые пути должны быть абсолютными, без пробелов и shell-символов. Каталог временного кода должен существовать, принадлежать SSH-пользователю и не допускать запись другими пользователями; каталог резервных копий — находиться вне каталога сайта. Не помещать локальный JSON в GitHub.
3. Нужен штатный Windows OpenSSH (`ssh`, `scp`) и существующий SSH-ключ. На сервере нужны Python 3, GnuPG, Git, PM2 и Nginx. Ничего не устанавливается автоматически. Для чтения всех настроек и памяти процесса требуются административные права.

## Две команды владельцу

Если предыдущая версия сообщила `NGINX_MIXED_SERVER_NAMES_REVIEW`, сначала выполните безопасную диагностику:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\SiteConfig-Backup.ps1 -Mode Diagnose
```

Можно явно добавить `-ConfigPath .\backup.local.json`. Путь по умолчанию теперь определяется в теле скрипта после привязки параметров, с fallback через PSCommandPath/MyInvocation; вычисления Join-Path с ещё пустым PSScriptRoot в param больше нет. Запускать следует сохранённый файл через `-File`, а не вставлять код через Invoke-Expression.

Diagnose читает только Nginx vhost-файлы: без env, PM2, архивов, пароля, GnuPG и даже `nginx -t`. В выводе — номера файла/блока, строка и безопасные server_name с классификацией; полные пути, тела конфигурации и значения переменных не печатаются. Создаётся и удаляется лишь приватный временный каталог кода и JSON выбора источников; действующие настройки не меняются. Результат `ELIGIBLE` означает, что проверка принадлежности пройдена; `REVIEW_REQUIRED` оставляет копирование заблокированным.

Среди имён должны быть подтверждённые домены из локального JSON (`OWNED_DOMAIN`). Дополнительно в том же блоке допускаются только `_`/пустое имя (`NEUTRAL_NAME_MARKER`) и точный IP SSH-цели из локального ServerAddress (`OWNED_SSH_TARGET_IP`). IP не определяется через DNS. Чужие DNS-имена, другие IP, переменные, wildcard и regex остаются `UNPROVEN_NAME` и блокируют копирование. Отдельные default/IP-only блоки без своего домена не включаются. Серверные DNS-имена сравниваются без учёта регистра и завершающей точки; объявления ищутся только в корректном server-контексте, а не среди аргументов других директив. Повторные symlink на один vhost не дублируются.

Ошибка прежней версии означала: в блоке, содержащем разрешённый домен, найден ещё один токен, который старая проверка не считала разрешённым. Источником мог быть реальный дополнительный server_name либо ложное срабатывание парсера, принимавшего слово server_name среди аргументов другой директивы за объявление. Конкретные имена на реальном сервере без вывода диагностики неизвестны. Не нужно добавлять все обнаруженные имена в Domains или удалять проверки.

Создать, проверить расшифрование и скачать:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\SiteConfig-Backup.ps1 -Mode Create
```

Проверить последнюю скачанную копию:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\SiteConfig-Backup.ps1 -Mode Check
```

Открыть PowerShell следует в папке со скриптом. Bypass действует только на этот запуск, постоянную политику Windows не меняет. Проверка SSH host key не отключается. Если сам SSH-ключ защищён парольной фразой, SSH может запросить её отдельно.

При создании новый случайный пароль архива длиной от 20 символов вводится **скрыто дважды**. При проверке — один раз. Сохранить пароль в менеджере паролей отдельно от архива: без него восстановление невозможно. Пароль не передаётся в argv, окружении, файлах и логах.

По умолчанию `.tar.gz.gpg` и `.sha256` сохраняются в **«Документы» → `SiteConfig-Backups`** текущего пользователя. Скрипт печатает фактический полный путь; перенаправление «Документов» учитывается. Оба файла нужно сохранять вместе. На сервере остаётся дополнительная зашифрованная копия в настроенном закрытом каталоге. Параметр `BackupDirectory` локального JSON позволяет выбрать другую папку, например на офисном диске.

Успех: `BACKUP_COMPLETE` и `LOCAL_SHA256_OK`; отдельная проверка: `BACKUP_CHECK_PASSED`. Для конкретного файла можно добавить `-Archive "ИМЯ_ФАЙЛА.tar.gz.gpg"`. При ошибке не считать копию проверенной.

## Содержимое и границы

- Все существующие production env-профили Next.js: `.env.production.local`, `.env.local`, `.env.production`, `.env`; также явно заданные Node `--env-file` внутри каталога приложения.
- Только выбранное PM2-приложение: параметры запуска и его фактические переменные для SMTP, Telegram, LexRadar, NEXT_PUBLIC и перечисленных Node/runtime/recipient ключей. Полный PM2 dump, посторонние shell-переменные и другие приложения не копируются.
- Только активные Nginx server-блоки с доменами из локального JSON и их конфигурационные includes. Общий файл с несколькими сайтами разделяется: чужие блоки не копируются. Дополнительные includes вне каталога Nginx разрешаются только точным списком `AdditionalNginxIncludes` в локальном JSON.
- `manifest.json` с путями, UID/GID, режимами, исходным SHA и SHA-256 каждого файла; `RESTORE.txt` с инструкцией восстановления.

Исходники, пользовательские данные, uploads, логи, `.git`, `.next`, `node_modules`, SSH-ключи, development env и произвольные серверные скрипты не копируются. TLS-сертификаты/приватные ключи и общая конфигурация Nginx с глобальными map/upstream также не включены: их нужно сохранить действующими либо отдельно восстановить/перевыпустить при потере сервера. Это резервная копия конфигурации одного сайта, а не образ сервера.

Несколько процессов с одним именем PM2, watch-режим, другой source SHA, внешние env, неизвестные includes и смешанные server_name приводят к остановке. Необычная топология требует адаптации; защита не обходится автоматически.

## Шифрование и проверка

Настройки и tar.gz обрабатываются в памяти. GnuPG использует **AES-256 + MDC**, S2K mode 3, SHA-512, count 65011712. Пароль поступает через отдельный анонимный pipe. Незашифрованный архив на диск не записывается. Core dump помощника отключён; его временный GPG-каталог удаляется. Временный код и JSON выбора источников находятся в закрытом каталоге; этот JSON содержит только пути и имена, без секретных настроек.

Create реально расшифровывает полученный ciphertext, сравнивает байты с исходным архивом и проверяет manifest перед сохранением. После скачивания Windows сверяет SHA-256. Сам SHA sidecar обнаруживает ошибки передачи, но не удостоверяет подлинность — для этого проверяется GPG MDC при расшифровании.

Check сначала проверяет локальный SHA, затем временно загружает только зашифрованный файл на сервер под новым случайным именем и проверяет GPG и manifest в памяти, без распаковки. Временный ciphertext удаляется в finally; при потере связи может остаться только зашифрованная копия. Нужен доступный сервер; установка GnuPG/Python на Windows не требуется. При потере сервера архив можно проверить и расшифровать на другой доверенной Linux-машине с GnuPG.

Скрипт не изменяет настройки, не сохраняет/перезапускает PM2, не перезагружает Nginx, не отправляет заявки и не меняет исходники. Перед запросом PM2 проверяется его существующий сокет; `PM2_HOME` задаётся явно, чтобы не запустить чужой или новый демон. Вывод ограничен статусами и путями ciphertext; env, сырой PM2 JSON, пароли и диагностические ответы команд не печатаются.

## Восстановление после отдельного разрешения

1. Проверить архив. На доверенной Linux-машине создать закрытый каталог вне web-root и синхронизации: `umask 077; mkdir -m 700 recovered`.
2. В bash включить `set -o pipefail`, затем выполнить `gpg --decrypt -- ИМЯ_АРХИВА.tar.gz.gpg | tar --no-same-owner --no-same-permissions -xzf - -C recovered`. Пароль запросит GnuPG. При ошибке любого этапа не использовать частичную распаковку.
3. Читать `RESTORE.txt` и `manifest.json`. Подготовить точный исходный SHA в отдельном release-каталоге. Вернуть env с прежними значениями и закрытыми правами; работающий SMTP не перенастраивать.
4. Восстанавливать из `pm2/ecosystem.app.json` только нужное приложение; проверить cwd/script/interpreter. Не выполнять общий `pm2 resurrect`.
5. Аккуратно вернуть только выбранные Nginx-блоки и snippets; не заменять файл, общий с другими сайтами. Проверить наличие TLS и глобальных зависимостей, затем `nginx -t`. Переключение и перезапуск сервисов — отдельное разрешённое действие.
6. Проверить статусы приложения и одну помеченную тестовую заявку. Расшифрованные рабочие копии удалить; учитывать snapshots/SSD и использовать защищённый зашифрованный диск.

```sh
python3 -B build.py
python3 -B -m unittest -v test_backup.py
pwsh -NoProfile -File test_wrapper.ps1
```

Все данные тестов синтетические. SSH/SCP в PowerShell-тесте полностью подменены; подключений к production нет. Проверка PowerShell 7 на Linux не заменяет настоящий запуск Windows PowerShell 5.1/OpenSSH. Подробнее — TEST_RESULTS.md.
